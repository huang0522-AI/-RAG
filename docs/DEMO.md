# 演示与答辩手册（广东教育政策问答 RAG）

> 本文所有数字均来自本机真实运行，未验证项会明确标注。

## 1. 一句话定位

把 68 条广东教育政策问答做成"可检索、可溯源、可演示"的问答服务：问一句，返回一段带来源编号的回答，外加一条能看清每一步花了多少时间的检索链路。

## 2. 链路四段 · 每段为什么需要它

1. **向量路（Embedding → Chroma → top20）**：处理"意思相近但用词不同"的问法，关键词对不上时仍能召回。
2. **关键词路（jieba → BM25 → top20）**：处理"专有词必须精确命中"的情况（如"二级乙等""立功登记表"），补向量的漏召。
3. **RRF 融合 + 精排**：两路结果分数不可比，用 RRF 只按排名等权融合；再用 LLM 对候选做一次相关性重排，把最该看的放到前面。
4. **生成（DeepSeek）**：只把 top5 证据拼进 prompt，要求逐句标注 `[n]` 来源、无据不答，确保答案能对上引用。

## 4. 三分钟讲解稿（口语化）

"这是一个教育政策问答系统，语料是 68 条广东教育政策的问答，切成 69 块。

用户问一句，我这边同时走两条路：一条是向量检索，负责‘意思相近’；一条是关键词 BM25，负责‘专有词精确命中’。因为我现在的 embedding 是 hashing 版本、没有真正的语义能力，所以关键词这条路尤其重要，两条路是互补的。

两条路各出 20 条，用 RRF 融合——注意是只按名次、等权融合，不调权重，因为两路的分数量纲完全不一样，硬加权反而不可解释。融合之后再用 DeepSeek 做一次 LLM 精排，从 20 条里挑最相关的 5 条。

最后只把这 5 条拼进 prompt，让模型逐句标注来源编号 `[n]`，没有依据就直接说没找到。返回给用户的除了答案，还有每条引用的文档、分数，以及一条 trace，能看到 embedding、混合检索、精排、生成各花了多少毫秒。

右边这个面板就是 trace 的可视化，这是我觉得最值得看的部分——每一步的代价都摆在这儿。"

## 7. 必答问题口径

**为什么用 RRF 而不是加权求和？**
向量相似度（0~1）和 BM25 分数（0~几十）量纲完全不同，直接加权需要额外归一化和调参，而且不同 query 的分布还会漂。RRF 只看名次、两路等权，简单、稳定、可解释，改一路不影响另一路的权重。

**为什么精排用 LLM 而不是 CrossEncoder？**
本环境装不了 sentence-transformers（torch 下载太慢），CrossEncoder 起不来。LLM 精排直接复用已有的 DeepSeek key，listwise 让模型输出候选编号排序，效果够用且零额外依赖；代价是每次多 ~0.8s 和一次外部调用。若环境允许，`local` 后端可无缝切回 CrossEncoder。

**为什么 embedding 是 hashing？**
同样是环境限制：无 torch、无 sentence-transformers、也没有可用的 embedding API key，所以自动降级到纯 Python 的哈希向量（blake2b 字符 n-gram，dim=512）。它只保证链路完整、可跑通，**没有语义能力**，同义问法主要靠 BM25 和 LLM 精排兜底。

**12/12 是否说明效果好？**
**不能这么说。**这 12 道题的题库是基于同一批语料构造的，100% 只说明"检索→融合→精排→生成"这条链路对已知问答是正确、稳定的；它**不代表对没见过的问法的泛化能力**。真实的评估需要一份独立标注、且不在语料里的问题集。

**这套东西的边界在哪？**
只在"教育政策问答"这个封闭语料上工作；embedding 无语义、单条问答较长导致精排/生成偏贵、对外部 DeepSeek 有依赖、单进程无鉴权。它适合做"可解释的检索链路演示"，不适合直接当生产问答网关。

## 8. 兜底方案

**断网 / 无 key（已实测）**
把 `DEEPSEEK_API_KEY` 置空后重启（不改代码）：
- `/health` → `generation.mode=extractive`、`rerank.mode=disabled`；
- 问「国家励志奖学金证书怎么下载？」→ **HTTP 200**，`gen_mode=extractive`，answer 仍含「旧版入口 / 粤省事」，citations 5 条非空。
- 恢复 key 重启后回到 `online`。
讲法："外部不可用时，精排自动停用、生成切到抽取式，直接把最相关的原文前两句拼出来，链路不断，只是不再加工。"

**模型加载失败（embedding）**
`auto` 会依次尝试 api → local → hashing；api 运行中失败也会自动落到 hashing，并在日志和 `/health` 里体现，服务不会因为模型加载失败而启动失败。

**彻底断网**
hashing embedding 与 BM25 完全离线可用；DeepSeek 不可达时重试一次后转 extractive，因此断网下仍能演示纯检索 + 抽取式回答。
